## Depth taxonomy

| Grade | Meaning | PARITY “done” allowed? |
|-------|---------|------------------------|
| `D0` | Absent in kotlin-tor | No |
| `D1` | Nameplate only (tiny registry/formatter, or parse-only / ack-only option) | No |
| `D2` | Partial semantics + some tests; missing major C control-flow / fields | No (stays 🟡) |
| `D3` | Hot-path wired; vectors/live tests for claimed C behavior | Yes |
| `D4` | Near C Tor depth for that unit (rare; audit required) | Yes |
| `N/A` | Intentionally not mirrored (JDK/Kotlin equivalent, deprecated `rend`, …) | N/A — document reason |

**Anti-false-done rules**

1. A PARITY row may not be ✅ unless every linked inventory row is ≥ `D3`.
2. Any Kotlin file whose KDoc contains `lite)` or `not ported` forces matching units ≤ `D2`.
3. Elevations must cite inventory `row_id` and may raise depth by one grade only with evidence (test name + C symbol).
4. `/loop` must consume the generated lowest-depth queue ([CTOR_MISSING_INVENTORY.md](CTOR_MISSING_INVENTORY.md)), not vibes.

## CSV schema

Columns in `generated/ctor_master_inventory.csv`:

| Column | Description |
|--------|-------------|
| `row_id` | Stable id (`L1:…`, `L2:…`, `L3:…`, `L4:…`) |
| `layer` | `1_module` \| `2_type` \| `3_op` \| `4_option` |
| `ctor_module` | e.g. `feature/dirauth`, `core/or` |
| `ctor_unit` | `.c` basename, `*_st.h` type, exported fn, or option field |
| `ctor_symbols` | Key typedefs / related symbols (semicolon-separated) |
| `ktor_path` | Kotlin path/class or `MISSING` |
| `depth` | `D0`–`D4` or `N/A` |
| `evidence` | LOC, lite KDoc, test name, match heuristic |
| `gaps` | Concrete missing behavior |
| `parity_board_id` | Optional PARITY section link |
